# Company 통합 테스트 시나리오

이 문서는 `company-service`에서 수행되는 통합(Scenario) 테스트의 비즈니스 흐름을 사람의 언어로 정의합니다. 모든 테스트는 `IntegrationTestSupport`를 상속받아 수행됩니다.

## 🛠️ 공통 전제 조건
- **환경**: SpringBoot 기반 통합 테스트 (`@SpringBootTest`)
- **도구**: `MockMvc`를 사용하여 API 호출 및 검증
- **인증/인가**: Gateway에서 전달되는 `X-User-Id`, `X-User-Role` 헤더를 수동으로 주입하여 권한별 동작을 검증함.
- **데이터 정합성**: `@Transactional`을 통해 각 테스트 종료 후 데이터를 자동 롤백함.

---

## 📋 시나리오 리스트

### 1. 업체 관리 핵심 흐름 (등록 -> 수정 -> 조회)
이 시나리오는 업체가 시스템에 등록된 후, 관리자에 의해 정보가 변경되고, 사용자가 이를 조회하는 일련의 과정을 검증합니다.

- **Step 1: 업체 신규 등록**
    - **행동**: `MASTER` 권한 헤더를 포함하여 `POST /api/v1/companies` 호출. (사업자 번호, 이름, 타입 등 포함)
    - **기대 결과**: 응답 상태 코드 `201 Created`를 반환하고, 응답 데이터에 생성된 `companyId`가 포함되어야 함.
- **Step 2: 업체 정보 수정**
    - **행동**: `HUB_MANAGER` 권한 헤더를 포함하여 `PATCH /api/v1/companies/{companyId}` 호출. (업체 이름 또는 타입을 변경)
    - **기대 결과**: 응답 상태 코드 `200 OK`를 반환하고, 응답 데이터에 수정된 내용이 반영되어야 함.
- **Step 3: 최종 상태 조회 및 검증**
    - **행동**: `CUSTOMER` 권한 헤더를 포함하여 `GET /api/v1/companies/{companyId}` 호출.
    - **기대 결과**: 응답 상태 코드 `200 OK`를 반환하며, Step 2에서 수정한 정보가 정확히 조회되어야 함.
